# 과유불급 RAG: Baseline과 개선 7종 비교

2026-10-02. **정답 출처 Recall@5는 Baseline 6/8=75%, 최종 조합 8/8=100%였다.** 이는 답변 정확도가 아니다. 최종 조합에서도 일반 설명의 상한섭취량 해석 오류가 남았다. 생성 결과 검토는 assistant의 1차 검토이며 사용자·전문가 검토는 미완료다.

## 문제 정의와 Baseline 기록

음식·카페인·비타민의 보고량을 계산하고 공식 근거와 함께 설명하는 서비스다. 최신 문서 136개를 페이지를 보존하여 1,500자/겹침 200자로 분할한 8,308개 청크를 사용했다. 임베딩은 `text-embedding-3-small` 1,536차원, 검색은 FAISS 정규화 cosine Top-5, 생성은 `gpt-4.1-mini-2025-04-14`이다.

Baseline은 카페인 자료가 실제로 있는데도 성인 권고량 질문과 대상별 복합 질문에서 KDRI 문서만 검색했다. 또한 Python이 올바른 계산값을 주어도 LLM이 한 음식만으로 안전·부족을 단정하고, 용량 없는 커피 잔 수를 문서의 일반 예시에 대입했다. 이 문제 때문에 검색 개선과 생성 제어를 분리해 실험했다.

Baseline 원시 결과는 `results/runs/baseline_01/`에 보존했다. 질문별 Top-5 본문·페이지·점수, 실제 답변, 계산 결과, 모델/질문/코퍼스 해시와 코드 스냅샷이 포함된다. 당시 보고서는 `evaluation_at_baseline.md`로 보존했다.

## 평가 질문과 비교 조건

`examples/evaluation_questions.jsonl`의 같은 12문항을 사용했다.

- 구조화 계산 3: 명시적 식품코드의 해파리냉채 400g, 표시 카페인 150mg × 3잔, 비타민 C 1,000mg × 2정.
- 정답형·표현 변경·키워드·복합·기준 해석 5: 성인 카페인, 하루 어느 정도까지, 디카페인, 성인/임산부/어린이 비교, 비타민 A 권장량과 UL 구분.
- 근거 없음 2: 오늘 학교 급식의 정확한 함량, 가상의 XYZ-999 제품 함량.
- 추가 확인 2: 용량 없는 커피 3잔, 식품코드와 인적 조건 없는 해파리냉채 400g.

정답 출처가 지정된 8문항만 source ID Recall@5 분모에 포함했다. 근거 없음·확인 질문 4개는 생성 단계에서 평가했다. 특정 출처 ID를 찾았다는 사실은 정답 passage를 찾았다는 뜻도, 정확하게 답했다는 뜻도 아니다.

모델·문서·질문 집합을 고정하고, 자연어 입력은 Baseline에서 이미 추출한 request JSON을 재사용했다. 따라서 **이 비교는 입력 추출 이후 단계에 대한 실험**이다. 정답 출처 목록은 검색/생성 입력에 넣지 않았다. 단독 방법은 Baseline에 한 요소만 적용했다. 인용 검증과 계산 강화에서 변경하지 않는 일반 답변은 원래 결과를 재사용했다. 모든 LLM 생성은 1회이며 난수 변동이나 통계적 유의성은 측정하지 않았다.

아래 인용 오류 수는 모든 저장 답변에 동일한 최신 ID 검사기를 적용한 문항 수다. 원래 Baseline의 단일 대괄호 검사보다 범위가 넓다. 인용 ID 오류 0이 근거 일치나 사실 정확도 100%를 뜻하지 않는다.

| Baseline | 6/8 · 75% | 4 | 기준선 |
| ① 하이브리드 | 7/8 · 87.5% | 4 | 일부 카페인 검색 회복, 디카페인 근거 누락 회귀. 미채택 |
| ② MMR | 6/8 · 75% | 3 | 카페인 검색 누락 해결 안 됨. 미채택 |
| ③ 재순위화 | 6/8 · 75% | 4 | 추가 LLM 호출에도 검색 개선 없음. 미채택 |

| ⑥ 계산·확인 강화 | 6/8 · 75% | 4 | 섭취 질문 5개를 코드로 설명. **채택** |

## 왜 이 조합을 선택했는가

**하이브리드:** 한국어 문자 bigram과 단어를 사용하는 BM25를 dense 순위와 RRF로 합쳤다. 성인 카페인 질문은 회복했지만 영어 FDA 디카페인 근거가 밀려났다. 복합 질문은 KR_CAFFEINE 출처 ID가 Top-5에 들어왔어도 실제 400mg/300mg 수치가 없는 청크였다. 출처 점수 향상이 곧 답변 개선은 아니었다.

**MMR:** dense 후보 50개에서 다양성을 높였지만 빠진 카페인 근거를 가져오지 못했다. 커피 잔당 함량을 임의로 대입하는 생성 오류도 남았다.

**재순위화:** dense 후보 20개를 같은 모델로 0~4점 평가했다. 후보 단계에서 필요한 근거가 빠진 경우 해결되지 않았다. 총량 450mg이 기준 400mg의 112.5%라는 비율을 ‘112.5% 초과’로 잘못 표현하는 문제도 남았다. 올바른 초과 비율은 12.5%다. 단순히 모델 호출을 추가하는 방식은 채택하지 않았다.

**주제 필터:** 수집 당시의 `linked_entities`를 이용해 카페인 질문이 카페인 자료에서 검색되도록 했다. 명시적 주제가 없으면 전체 검색으로 돌아간다. 12개 개발 문항에서는 별도 재순위화 호출 없이 8/8 출처를 찾았다. 다만 필터만으로 생성의 계산 해석 오류는 해결되지 않았다.

**압축:** 생성 입력 토큰은 139,393개에서 75,885개로 약 45.6% 줄었다. 그러나 표현 변경 카페인 질문에서 필요한 400mg/300mg 문장이 제거되어 모델이 수치를 답하지 못했다. 원래 검색한 source ID는 같아 Recall@5는 이 손실을 포착하지 못했다.

**계산·확인 강화:** 요청에 섭취 항목이 있으면 Python 계산값과 판정 status를 직접 설명하도록 바꿨다. 잔당 함량을 추정하지 않고, RNI/EAR/AI를 과다 기준으로 바꾸지 않는다. 후보 음식코드도 답변에 직접 표시한다. 수치가 `reference_max`에 있는 미만 권고도 누락하지 않도록 추가 경계 테스트로 검증했다.

**인용 검증:** `[T1, D1~D5]`, `(T1, D1~D5)` 같은 묶음/범위 표기를 검사하고 제공되지 않은 ID를 제거한다. LLM의 사실 문장을 다시 쓰는 기능은 아니며, 인용된 문서가 주장을 뒷받침하는지는 별도 검토해야 한다.

## Baseline과 최종 답변의 실제 변화

| 문항 | Baseline | 최종 조합 |
|---|---|---|
| 해파리냉채 400g | 계산값은 맞지만 안전범위·철 부족 등 임의 판정 | 244kcal·나트륨 1,356mg 등 계산값을 표시하고 하루 전체 판단은 보류 |
| 카페인 150mg × 3잔 | 450mg, 기준 400mg 대비 112.5%로 계산 | 450mg과 최대 일일 권고 400mg 초과만 명확히 설명 |
| 비타민 C 1,000mg × 2정 | UL과 ‘최대 권고 상한선’ 용어 혼합 | 보고량 2,000mg이 UL을 넘지 않지만 다른 급원 섭취는 미확인이라고 설명 |
| 성인 카페인 / 대상별 복합 | 근거 부족으로 답하지 못함 | 해당 식약처 근거를 찾아 답함 |
| 용량 없는 커피 3잔 | 309~396mg으로 추정 후 비초과 판단 | 용량·함량을 추정하지 않고 추가 정보 요청 |
| 식품코드 없는 해파리냉채 | 코드 요청만 하고 후보는 답변에 없음 | 서로 다른 출처·단위의 후보 4개를 코드와 함께 표시 |
| 학교 급식 / 가상 제품 | 수치를 만들지 않지만 없는 T1 인용 | 수치를 만들지 않고 잘못된 근거 ID 제거 |
| 비타민 A 기준 설명 | 권장량 초과와 UL 초과를 구분 | 핵심 구분은 유지했지만 UL을 부작용 수준보다 높다고 서술하는 근거 없는 해석이 추가됨. **회귀로 기록** |

마지막 일반 설명 오류 때문에 전체 답변 정확도를 100%라고 결론 내리지 않는다. 검색 개선·코드 계산·인용 정리는 유효했지만, 일반 지식 설명에는 별도의 근거 함의 검사와 사용자/전문가 검토가 필요하다. 최종 생성 결과가 마음에 들 때까지 반복하여 고른 실험이 아니다.

## 토큰 및 실행 이력

| 방법 | 생성 입력 토큰 | 추가 재순위화 입력 토큰 |
|---|---:|---:|
| Baseline | 139,393 | 0 |
| 하이브리드 | 149,728 | 0 |
| MMR | 136,196 | 0 |
| 재순위화 | 139,425 | 99,180 |
| 주제 필터 | 138,055 | 0 |
| 압축 | 75,885 | 0 |
| 최종 조합 | 26,610 | 0 |

최종 조합은 5문항을 코드로 설명하고 7문항만 LLM으로 생성해 **생성 입력 토큰이 약 80.9% 감소**했다. 이 표는 입력 추출·임베딩·실패/중단 호출을 제외한 기록된 성공 호출이며 API 총 청구액이 아니다. guard/citations 단독 실험은 원래 생성 답변을 재사용한 부분이 있어 신규 생성 토큰 0을 서비스 원가 0으로 해석하지 않는다. 캐시와 동시 실행 때문에 지연시간 우열은 결론 내리지 않았다.

- `ablation_01/`: 7개 단독 방법의 최초 결과. 재순위화 후보 형식 오류 후 완료한 문항을 보존하여 재개했다.
- `rerank_validated_01/rerank/`: 형식 보완 전후가 섞이지 않도록 같은 보완 설정으로 12문항 전체 재실행한 최종 재순위화 비교.
- `combined_01/`: 최초 조합 결과 보존.
- `final_validation_01/`: 권고값이 max 열에 저장된 경계를 보완한 guard와 조합 재검증.
- `final_01/`: 직전 조합의 원시 답변을 다시 생성하지 않고 소괄호 인용 형식까지 보완한 최종 결과. 원시 답변·변경 전 답변을 모두 보존.

## 검증과 한계

25개 로컬 테스트가 통과했다. 원래 단위·음식 계산 검증에 단독 변경 분리, BM25·MMR·RRF, 압축 시 조건 보존, 인용 범위 처리, 잔당 함량 추정 방지, 엄격한 미만 경계, 빈 환경변수 예시 처리 등을 추가했다. 자연어 음식·커피·비타민 입력 3개도 별도 실행 검증을 완료했고 고정 12문항 점수에 가산하지 않는다.

이 12문항은 개선 설정 선택에 사용한 **개발 평가셋**이다. 카페인 비중이 높고 식품·비타민·복합 섭취 전체를 대표하지 않는다. 독립 평가셋, 여러 번의 생성 반복, 실제 사용자/전문가 검토가 필요하다. OCR 3개 출처, EFSA 부록 8개, 전체 표·그림 검토 및 성분 형태별 보류는 여전히 남아 있다.

공개 파일만 복사한 환경에서도 23개 테스트 통과·전체 DB용 2개 skip과 가상 데이터 실행 성공을 확인했다. 현재 설치된 Python 패키지를 사용하는 검증이며 GitHub Actions 원격 실행 또는 새 환경의 패키지 다운로드까지 완료한 것은 아니다. 제3자 원문·DB·임베딩·키·로컬 실행 로그는 GitHub 공개 대상에서 제외한다.


## 새로운 자연어 질문 24개 평가 — 2026-10-02

기존 12문항은 개선 방법 선택에 사용했다. 선택한 최종 조합을 그대로 두고 음식·카페인·비타민·예외 상황 각 6개, 총 24개의 새 질문을 실행했다. 질문과 기대 행동·금지 행동·숫자 기대값은 실행 전에 [질문 파일](../examples/holdout_questions_24.jsonl)과 [평가 계획](../examples/holdout_plan.json)에 고정했다. 이전 실험과 달리 자연어 입력 구조화부터 매번 실행했으며 정답 정보는 모델 입력에 포함하지 않았다.

모델은 `gpt-4.1-mini-2025-04-14`, 구성은 주제 필터 + 계산·확인 강화 + 인용 검증이다. 질문·계획·핵심 코드 4개 파일의 SHA-256을 저장했고 실행 후와 검토 완료 시 동일함을 확인했다. 평가 도중 시스템을 수정하거나 실패 문항만 재생성하지 않았다. 새 질문에서는 최종 조합만 실행했으므로 Baseline과의 개선율을 계산하지 않는다.

| 구분 | 결과 | 해석 범위 |
|---|---:|---|
| 실행 완료 | 24/24 | 실행 예외 0건 |

### 새로 확인한 실패 원인과 다음 개선 후보

1. **입력 보존 검증:** 음수 `-200g`이 `200g`으로 바뀌어 계산됐다. 비타민 A의 `ug_RAE`는 `ug`로 바뀌었고, 실제 섭취 진술이 없는 900mg도 섭취 기록으로 추출됐다. Python 계산이 정확해도 잘못 추출한 입력을 계산하면 전체 결과는 틀린다. 자연어 원문과 추출 값·부호·단위·섭취 의도의 대조가 우선이다.
2. **문장 단위 근거 확인:** 나트륨 설명에 칼륨의 근거가 사용됐고, 나트륨/소금 답변은 같은 답변 안에서 비교 방향이 뒤집혔다. 같은 KDRI 출처 ID를 검색하거나 유효한 인용 ID를 붙이는 것만으로 이를 검출할 수 없다. 해당 성분·해당 주장에 맞는 문맥인지 확인해야 한다.
3. **계산 답변의 설명 범위:** B12의 UL 미설정 상태는 계산에 있었지만 답변에서 빠졌다. 수유 조건의 개별 확인, 제품별 카페인 함량 확인도 누락됐다. 고정 렌더러에서 상태와 질문의 하위 요구를 반영할 필요가 있다.

위 항목은 개선 후보이며 이번 평가에서 시스템에 적용하지 않았다. 특히 음수 입력 실패는 사전 숫자 체크가 없는 예외 문항이므로 **27/27 통과에 포함되지 않는다**. 자동 계산 점수와 최종 답변 검토를 함께 보고해야 하는 이유다.

질문은 기존 시스템을 아는 상태에서 만든 새 시나리오로, 외부의 맹검 평가셋이 아니다. 각 질문 1회 실행이며 반복 안정성·전문가 판정은 미검증이다. 이 결과로 개선하면 24문항도 회귀/개발 평가셋이 되므로 이후 성능 주장은 또 다른 미사용 질문으로 확인해야 한다.

로컬 원시 기록은 `results/holdout/new_questions_24_01/`에 있다. 자동 결과 `summary.json`과 최초 manifest의 검토 대기 표기는 실행 시점 기록으로 보존하고, 완료된 내용 검토는 별도 `assistant_review.json`에 저장했다. 원시 검색 본문은 공개하지 않고 질문·계획·집계·검토 의견만 공개 대상으로 준비했다.

정리 후 기존 자동 테스트 25개를 다시 실행해 통과했고, 새 평가기의 숫자 체크가 오답 값과 누락 값을 실패 처리하는 것도 확인했다. 기존 음수 거부 테스트는 구조화된 입력의 검증이므로, 자연어 추출 단계에서 부호가 사라지는 이번 실패를 포착하지 못한다. 질문·계획·핵심 코드 해시는 계속 동일하다.

- 실제 섭취와 가정·답변 지시를 구분한다. 원문에서 청소년을 명시했다면 그 조건을 유지하며, 나이만 보고 임의의 청소년 경계를 추가하지 않는다. 이는 모든 한국어 표현을 완벽하게 검증하는 형식 증명은 아니다.
- B12의 UL 미설정 의미와 수유 시 개별 확인 안내를 렌더러에 추가했다. 식품의 모든 미설정 행마다 같은 문구를 반복하는 부작용은 제거했다.
- 처방약 임의 변경 및 근거 조작·보편적 안전 단정 요구는 서비스 범위 안내로 처리한다. 무관한 영양 문헌을 근거처럼 붙이지 않는다.
- 일반 설명의 근거 선택·검토를 추가한 두 구현도 시험했다. 첫 구현은 원문 인용문 불일치와 검토 모델의 재작성 문제가 있었고, 두 번째 구현은 단락 ID를 선택하게 했지만 정상 설명·정보 부족 안내를 삭제했다. 출처 검색 점수만 보고 채택하지 않고 `evidence_review=false`로 제외했다. 실험 코드는 선택 가능한 기능으로 남아 있으나 기본 구성이나 개선 성과에 포함하지 않는다.

중간 기록 `revision_24_01`, `revision_12_01`, `fresh_12_01`, `revision_24_02`, `revision_12_02`, `fresh_8_01`도 보존했다. 중간 미사용 질문을 보고 코드를 수정했으므로 이후에는 미사용 성능으로 부르지 않는다. 이는 같은 코드의 결과를 반복해 좋은 답변만 선택한 기록이 아니라, 코드 변경에 따라 전체 평가를 다시 실행한 이력이다. 각 실행의 코드·질문·계획 해시와 스냅샷으로 구분한다.

### 남은 오류와 검증 범위

일반 설명의 문제는 해결되지 않았다. 최종24에서 당류의 별도 표기 의무를 근거 없이 추가했고, 나트륨 설명에 칼륨 UL 문맥을 적용했으며, 소금/나트륨 비교 방향은 고쳤지만 인용 문맥에 없는 환산 수치를 추가했다. 처음12의 비타민 A 기준 설명과 추가8의 대상 미확인 비타민 C 설명에도 문제가 남는다. 제품 표시 확인 안내 누락도 남아 있다. **입력 검증·코드 계산 개선과 일반 설명의 사실 검증을 구분해야 한다.**

자동 테스트는 총36개 통과했다. 공개 파일만 복사한 별도 디렉터리에서는34개 통과·실제 DB용2개 skip, API 없는 가상 음식 계산 성공을 확인했다. 키·원문·DB는 복사하지 않았다. GitHub 원격 push/Actions 실행은 수행하지 않았다. 최종48문항 실행 중 핵심 코드·질문·평가 계획 해시가 바뀌지 않았으며 문서 정리 시 다시 확인했다. 입력 구조화 토큰까지 포함한 API 총비용은 기록하지 않았으므로 비용 절감률을 새 버전에 적용하지 않는다.


## 제출 버전: 검증된 개념 설명과 코드 환산

직전24문항에서 남은 총당류 표기 의무 주장, 다른 성분의 UL 근거 사용, 근거 없는 소금 환산 수치를 수정했다. LLM이 설명을 다시 검토하는 방식을 재채택하지 않고, **검증한 개념4종에만 원문 앵커와 고정 설명·계산을 적용**했다. 이 범위는 기준 종류 구분, 총당류/첨가당 구분, 여러 급원 카페인 합산, 나트륨/소금 환산이다. 원문 청크 ID·본문 SHA-256을 확인하며 근거가 없거나 달라지면 해당 설명을 보류한다.

| 평가셋 | 실행 | 출처 ID 성공 | 숫자 체크 | assistant 내용 검토 |
|---|---:|---:|---:|---|
| 기존24 회귀 | 24/24 | 13/13 | 27/27 | 충족24·부분0·실패0 |
| 처음12 회귀 | 12/12 | 8/8 | 기존 계산 예제 별도 확인 | 충족10·부분2·실패0 |
| 기존8 회귀 | 8/8 | 3/3 | 4/4 | 충족8·부분0·실패0 |
| 미사용8 추가 점검 | 8/8 | 7/7 | 7/7 | 충족8·부분0·실패0 |

기존24는 직전 충족20·부분1·실패3에서 충족24로 바뀌었다. 처음12의 제품/급식 근거 없음 질문은 함량을 만들지 않았지만 정보 부재 안내에 불필요한 인용을 붙여 부분 충족으로 유지했다. 모든 실행에서 예외 및 없는 인용 ID는0건이었다. 인용 ID 성공은 의미 정확도의 증명이 아니다. 또한 개념 경로의 출처 선택은 dense 검색이 아니라 검증된 앵커 조회이므로 검색 모델 자체의 성능 상승이라고 부르지 않는다.

고정 계획은 [release_evaluation_plan.json](../examples/release_evaluation_plan.json), 미사용 질문은 [release_fresh_questions_8.jsonl](../examples/release_fresh_questions_8.jsonl), 문항별 검토와 해시는 [release_summary.json](release_summary.json)에 있다. 원시 결과는 로컬 `results/holdout/release_*`에 보존했다. 원래 질문과 gold를 수정하지 않았고, 새8문항도 실행 전에 고정했다. 기존 질문의 실패를 보고 규칙을 추가했으므로 이는 범위를 제한한 개선이며 전체 영양 질문에 대한 일반화 성능을 의미하지 않는다.

### 원문과 구현의 연결

- 총당류/첨가당: KDRI2025 에너지·다량영양소, 물리92쪽의 정의. 법적 표시 의무는 설명하지 않으며 별도 법적 질문은 근거 부족으로 보류한다.
- 기준 종류: 같은 권 물리23~24쪽의 EAR/RNI/AI/UL 목적과 한계. 특정 성분의 UL 미설정 이유를 다른 성분에서 가져오지 않는다.
- 나트륨/소금: KDRI2025 무기질 물리144쪽의 소금5g과 나트륨2000mg 대응에서 **근사 환산계수2.5**를 사용한다. 이 대응을 개인별 섭취 권고로 적용하지 않는다. Decimal 함수에서 양수·단위·방향을 확인하고, 실제 제품 소금 함량과 근사 환산량을 구분한다. 원래 소금 질문의5000mg/800mg 방향도 별도 확인했다.
- 여러 급원 카페인: FDA의 전체 급원을 함께 고려하라는 문맥을 연결하고 제품별 표시 함량 확인을 안내한다.

### 검증과 남은 범위

로컬 자동 테스트44개가 통과했다. 새 테스트는 근사환산 양방향·mg/g 단위·음수/비유한값 거부, 숫자의 대상 연결, 없는/변경된 근거에서 보류, 법적 의무로 확대하지 않기, 근거 원문 앵커 검증을 포함한다. 마지막 원문 검증 테스트는 실제 인덱스가 없는 공개 환경에서는 skip한다.

검증된 개념은 자연어 패턴으로 분기하므로 복잡한 복합 질문·부정 표현·낯선 표현에는 누락 또는 과도한 분기가 가능하다. 그 밖의 질문은 자유 생성 경로가 남아 있다. 새8문항은 비맹검·단회·소표본이며 전문가 정확도100%라는 결론을 내릴 수 없다. 범위 밖 항목은 보류하는 동작도 평가했다. 과거 OCR·부록·표 전수검토의 데이터 한계도 그대로 남아 있다.

공개 소스 묶음 검증: 원본 데이터·키 없이 복사한 환경에서44개 중41개 테스트 통과·실제 DB/원문 인덱스용3개 skip을 확인했고, API 없는 가상 음식 계산도 성공했다. ZIP의 모든 파일 SHA-256 및 키·PDF·DB·임베딩·원시 로그 제외를 검사했다. 원격 CI 결과와는 구분한다.
