# 과유불급 RAG 평가 — 제출 점검본

2026-10-02. 개발 비교 단계에서 source ID Recall@5는 Baseline 6/8 → 선택 조합 8/8로 개선됐다. 이후 새 질문의 실패를 바탕으로 원문 검증과 검증된 개념 4종을 추가했고, 이번 제출 점검에서 개수 누락·항목 간 수치 혼동을 수정했다. **현재 검증은 자동 테스트 53개 통과, 기존 24문항 내용 검토 23충족·1부분, 기존 12문항 10충족·2부분, 추가 4문항 3충족·1실패(안전하게 계산 보류)**다. 과거의 24/24는 이전 실행 결과이며 현재 실행과 구분한다.

내용 판단은 assistant의 단회 검토다. 전문가·사용자 검증, 임상 정확도, 일반 질문 정확도 100%를 의미하지 않는다. 출처 검색·수치 검사·답변 품질을 별도로 기록한다.

모든 실행에서 예외와 제공되지 않은 인용 ID는 0이었다. 출처가 사전 지정된 문항만 Recall 분모에 포함한다. `G02`는 식품 DB 계산 질문으로 검색 정답 출처를 지정하지 않았다. 12문항 중 구조화 요청 3개는 직접 JSON을 사용하고 나머지는 자연어를 추출한다. 24문항과 추가 4문항은 자연어 추출부터 실행했다.

같은 코드·선택 설정을 고정하고 질문·계획·코드·코퍼스 해시를 실행 전후 대조했다. 실패 문항만 반복 생성해 좋은 답변으로 교체하지 않았다. 현재 집계와 문항별 판단은 [submission_review_summary.json](https://github.com/dfklsna/gwayubulgeup-rag-capstone/blob/main/results/submission_review_summary.json), 추가 질문·계획은 [질문 4개](https://github.com/dfklsna/gwayubulgeup-rag-capstone/blob/main/examples/relationship_questions_4.jsonl)와 [제출 점검 계획](https://github.com/dfklsna/gwayubulgeup-rag-capstone/blob/main/examples/submission_review_plan.json)에 있다. 이 4개는 시스템을 알고 작성한 진단 질문이며 독립 맹검셋이 아니다.

## 코드·세 파일 제출 검증

실제 데이터가 있는 환경은 53개 테스트 전부 통과했다. 공개 소스 환경은 50개 통과·실제 DB/코퍼스를 요구하는 3개 skip이다. 과거 25·36·44개 테스트 기록은 개발 이력이며 현재 테스트 수와 합산하지 않는다.

이번에 추가한 검증은 잘못 추출한 `count=1` 거부, 체중을 음식량으로 사용하지 않기, 다른 영양소 수치 차용 거부, 총량 이중 곱셈 방지, 한국어 개수·개당 함량 분리, 잔 단위 중복 곱셈 방지다. 올바른 입력도 함께 검사했다.

정확히 세 파일만 빈 폴더에 복사한 뒤 `python -I -S capstone_compare.py --help`, `--demo`, `--requirements`를 실행했다. `-I -S`로 외부 설치 패키지와 환경 경로의 도움을 차단한 상태에서도 성공했다. `src/`·`results/` 계층을 유지한 복사도 검사했고, 별도 합성 DB·요청과 설치 패키지를 제공한 `calculate` 경로도 확인했다. 내장 모듈과 저장소 원본의 일치 검사도 통과했다.

이는 **세 파일의 실행 진입점·오프라인 계산과 로컬 모듈 의존성 해결**을 검증한 것이다. 세 파일에 실제 데이터·임베딩·API 키·pip 패키지를 포함하지 않는다. 전체 RAG는 해당 외부 자원이 있어야 실행된다. 자세한 조건은 함께 제출하는 설계 문서에 적었다.

## 개발 비교: Baseline과 단독 개선 7종

12개 질문에는 음식·카페인·비타민 계산 3개, 근거 설명 5개, 근거 없음 2개, 추가 확인 2개가 포함된다. 모델은 `gpt-4.1-mini-2025-04-14`, 임베딩은 `text-embedding-3-small`, 데이터는 최신136문서·8,308청크로 고정했다. 1,500자/겹침200자, 정규화 cosine Top-5를 사용했다. 첫 비교에서는 Baseline의 구조화 입력을 재사용했으므로 자연어 추출 정확도 개선으로 해석하지 않는다. 정답 출처는 모델에 전달하지 않았다.

| 개발 단계 방법 | 출처 Recall@5 | 없는 인용 ID 문항 /12 | 선택 이유 |
|---|---:|---:|---|
| Baseline | 6/8 | 4 | 카페인 근거 누락·계산 해석 오류 확인 |
| 하이브리드 | 7/8 | 4 | 일부 개선이나 디카페인 근거 누락 회귀 |
| MMR | 6/8 | 3 | 카페인 검색 누락 미해결 |
| 재순위화 | 6/8 | 4 | 추가 모델 호출에도 출처 개선 없음 |
| 주제 필터 | 8/8 | 2 | 명시적 주제 문서 검색으로 카페인 근거 회복; 채택 |
| 문맥 압축 | 6/8 | 4 | 필요한 권고 수치 삭제; 미채택 |
| 계산·확인 강화 | 6/8 | 4 | 섭취5문항을 코드로 설명; 채택 |
| 인용 ID 검사 | 6/8 | 0 | 없는 ID 제거; 채택 |
| 개발 선택 조합 | 8/8 | 0 | 주제 필터 + 계산·확인 + 인용 검사 |

Baseline은 한 음식만으로 안전·부족을 단정하거나 잔당 카페인을 추정했다. 계산·확인 강화는 해파리냉채400g의 244kcal·나트륨1356mg, 카페인150mg×3잔=450mg 같은 계산을 유지하며 하루 안전 판단을 보류했다. 개발 선택 조합에서도 UL 설명 오류가 남았고, 이후 개념 처리 보완의 대상이 됐다.

압축은 생성 입력 토큰을 139,393→75,885로 줄였지만 필요한 수치도 삭제했다. 개발 선택 조합은 섭취5문항을 코드로 설명하여 생성 입력 26,610토큰을 기록했다. 입력 추출·임베딩·실패 호출을 제외한 성공 호출 집계이며 총 API 비용이 아니다. 통계적 유의성이나 지연시간 우열은 평가하지 않았다. [단독 비교 집계](https://github.com/dfklsna/gwayubulgeup-rag-capstone/blob/main/results/comparison_summary.json)에 세부 기록이 있다.

## 결론과 적용 한계

개발 질문에서는 검색 누락을 줄였고 결정적 계산·원문 관계 검증으로 확인한 오계산 경로를 막았다. 다만 관계 검증은 보수적 규칙이며 완전한 한국어 이해를 보장하지 않는다. 정상 입력 보류, 일반 생성의 근거 함의·관할 범위·불필요한 인용, 여러 항목 합산 미지원은 남아 있다. OCR·추가 첨부·전수 표 검토도 미완료다. 초기 냉수욕·수중침수 수집 자료는 현재 영양 기능의 필수 근거가 아니며 데이터 범위는 설계 문서에 설명했다.

코드 실행·특정 회귀 사례의 통과와 영양 분석 서비스 전체의 정확도를 구분한다. 다음 평가는 외부 작성 질문·복잡한 총량/개수 문장·항목 관계·반복 실행·사용자 및 전문가 검토가 필요하다.
