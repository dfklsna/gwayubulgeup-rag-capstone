# 과유불급 RAG 평가

2026-10-02. 개발 비교 단계에서 source ID Recall@5는 Baseline 6/8 → 선택 조합 8/8이었다. 이후 입력 관계·프로필·원문 검증을 보완했고, 이번에는 재순위화 실행 오류, 음식명/식품코드 불일치, Baseline 도구 인용 허용 조건, 음식 하루 총량 상태 전달을 수정했다. **현재 자동 테스트는 실제 데이터 환경102개 통과, 공개 환경99개 통과·3개 skip이다. 기존24문항은22충족·1부분·1실패, 개발12는9충족·3부분, 관계4는3충족·1실패, 진단4는4충족이다.** 이전24/24를 현재 결과로 사용하지 않는다.

내용 판단은 assistant의 단회 검토다. 전문가·사용자 검증, 임상 정확도, 일반 질문 정확도를 의미하지 않는다. 출처 검색·수치 검사·답변 품질을 별도로 기록한다.

### 실행 경로 수정 검증

이전 커밋8fbf944를 별도 폴더로 복원해 새 테스트4개를 실행했다. rerank의 NameError1개, 다른 음식 코드 계산·하루 총량 상태·Baseline T1 오판의 실패3개를 재현했고 수정 후 통과했다. 회귀 테스트는 실제 rerank 분기와 응답 ID 재시도, 합성 음식 A/B의 이름·코드 교차, 정상 등록명/별칭, 자연어 parse→calculate 차단, 실제 음식 기준 함수→답변의 하루 총량 일치, Baseline clarification-only 인용을 검사한다.

실제 API에서 `ask --variant rerank`의 후보20개 평가와 답변 생성이 완료됐고, `compare --variants rerank`도 기존12문항을 모두 완료했다. 이 실행의 source Recall@5는6/8, 없는 인용 ID가 포함된 문항은5/12다. 별도 CLI 실행에도 근거 없는 T1 인용1개가 남았다. **실행 오류 복구와 답변 품질은 구분한다.** 단독 rerank의 답변 내용은 추가 채점하지 않았으며 과거 개발 ablation 수치를 이 결과로 덮어쓰지 않았다. 선택 조합에는 rerank를 사용하지 않는다.

앞선 프로필/개수 검증 단계의 실행과 과도한 보류를 수정한 과정은 [context_grounding_summary.json](https://github.com/dfklsna/gwayubulgeup-rag-capstone/blob/main/results/context_grounding_summary.json)에 보존했다. 일반 생성의 출력 차이를 이번 수정의 성능 향상으로 해석하지 않는다.

## 코드·독립 실행 검증

실제 데이터가 있는 환경은 102개 테스트 전부 통과했다. 공개 소스 환경은 99개 통과·실제 DB/코퍼스를 요구하는 3개 skip이다. 과거 25·36·44·53·61·67·94개 테스트 기록은 개발 이력이며 현재 테스트 수와 합산하지 않는다.

누적 회귀 검증은 잘못 추출한 `count=1` 거부, 체중을 음식량으로 사용하지 않기, 다른 영양소 수치 차용 거부, 총량 이중 곱셈 방지, 한국어 개수·개당 함량 분리, 잔 단위 중복 곱셈 방지다. 추가로 성분명/ID 불일치, 알려지지 않은 ID, 누락된 음식·철 성분의 수치 차용, 뒤 문장 개수·다른 약·부정 표현, 기준값 차용, 실제 parse→calculate 차단을 검사했다. 추가로 영양소·음식의 앞쪽/뒤쪽 누락, 같은 숫자로 누락을 가리는 경우, 모든 항목 누락, 체중/기준값 제외, 정상 복수 항목 보존을 검사했다. 부분 추출을 허용하던 과거 테스트 기대값도 전체 항목 보존 원칙에 맞게 수정했다. 올바른 입력도 함께 검사했다. 이전 보완에는 임의 프로필·임신/수유와 성인 기준 혼용·다른 사람/기준 문장의 정보·프로필 범위, 같은 절의 커피/다른 약/영양제 개수 차용, 진행형·명사형의 양방향 누락, 부분 evidence, 가정·부정, 허위 하루 전체 여부를 추가했다. 실제 parse→calculate 경로의 차단과 추출 스키마의 허용값 제한도 검사했다.

정확히 세 파일만 빈 폴더에 복사한 뒤 `python -I -S capstone_compare.py --help`, `--demo`, `--requirements`를 실행했다. `-I -S`로 외부 설치 패키지와 환경 경로의 도움을 차단한 상태에서도 성공했다. `src/`·`results/` 계층을 유지한 복사도 검사했고, 별도 합성 DB·요청과 설치 패키지를 제공한 `calculate` 경로도 확인했다. 내장 모듈과 저장소 원본의 일치 검사도 통과했다. 별도 [교차 검증 스크립트](https://github.com/dfklsna/gwayubulgeup-rag-capstone/blob/main/scripts/crosscheck_submission.py)는71개 정상/오류 입력을 별도 프로세스에서 전체 소스와 세 파일에 각각 적용해 예상 승인/보류 및 결과 일치를 확인한다. 이 검사는 API 없이 수행하며 실제 LLM의 오류 빈도 측정과 구분한다. 별도 가상환경에서 requirements-preprocessing.txt 전체 설치, pip check, 전처리 import와 lxml 파싱, 공개 소스102개 테스트 및71개 교차 검증을 다시 통과했다.

이는 **독립 실행 코드의 진입점·오프라인 계산과 로컬 모듈 의존성 해결**을 검증한 것이다. 세 파일에 실제 데이터·임베딩·API 키·pip 패키지를 포함하지 않는다. 전체 RAG는 해당 외부 자원이 있어야 실행된다. 자세한 조건은 설계 문서에 적었다.

## 개발 비교: Baseline과 단독 개선 7종

12개 질문에는 음식·카페인·비타민 계산 3개, 근거 설명 5개, 근거 없음 2개, 추가 확인 2개가 포함된다. 모델은 `gpt-4.1-mini-2025-04-14`, 임베딩은 `text-embedding-3-small`, 데이터는 최신136문서·8,308청크로 고정했다. 1,500자/겹침200자, 정규화 cosine Top-5를 사용했다. 첫 비교에서는 Baseline의 구조화 입력을 재사용했으므로 자연어 추출 정확도 개선으로 해석하지 않는다. 정답 출처는 모델에 전달하지 않았다.

개발 질문에서는 검색 누락을 줄였고 결정적 계산·원문 관계 검증으로 확인한 오계산 경로를 막았다. 다만 관계 검증은 보수적 규칙이며 완전한 한국어 이해를 보장하지 않는다. 정상 입력 보류, 일반 생성의 근거 함의·관할 범위·불필요한 인용, 여러 항목 합산 미지원은 남아 있다. OCR·추가 첨부·전수 표 검토도 미완료다. 초기 냉수욕·수중침수 수집 자료는 현재 영양 기능의 필수 근거가 아니며 데이터 범위는 설계 문서에 설명했다.

코드 실행·특정 회귀 사례의 통과와 영양 분석 서비스 전체의 정확도를 구분한다. 다음 평가는 외부 작성 질문·복잡한 총량/개수 문장·항목 관계·반복 실행·사용자 및 전문가 검토가 필요하다.
